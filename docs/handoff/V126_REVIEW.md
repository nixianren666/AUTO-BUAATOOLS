# v1.2.6 全面审查：准确性、误操作防护、后台可靠性与安全

日期：2026-10-14，北京时间。对象是用户认可的 v1.2.6；不恢复微信，不将 v1.3 专有故障混入本版。技术对照来自固定版本的 [UBAA / AutoBoya 独立机制研究](UPSTREAM_MECHANISMS.md)，结论以本轮源码和隔离验证为准。

## 结论

**v1.2.6 已有基本防线，但尚不能按“可靠常驻、绝不误签/误抢、账号高强度保护”的标准交付。** 优先问题在写操作身份与状态复核、考核假通过、抢课批次冲突、管理面信任边界、TLS 和前端事件注入；不是继续添加功能就能弥补。

严重性口径：P1=应在可靠使用/下一次发布前优先修复；P2=明显缺口或条件性风险，需要补全契约/测试。没有发现正在发生的攻击或学校已实施的处罚，不使用“已经被盗”“必定被封”等断言。

版本下架是单独的交付事项。审查开始时 GitHub main 和同级 Git HEAD 都是 fcc5131、v1.3.1/v1.3.2 Release 可见、默认 EXE 属于撤回系列；下架执行及最后状态记入 [VERSION_WITHDRAWAL.md](VERSION_WITHDRAWAL.md)，不能把撤回要求记作完成证据。

## 1. 先肯定已经存在的有效机制

- 常规调度限定课前10分钟，随机计划、最多3次逻辑尝试；成功后重新读取课表。
- 自动博雅强制排除无自主定位点列表的课程；存在校区、容量、开放时间、状态和已选博雅冲突检查。
- 白天课池网络同步60秒、已选同步300秒；不是仅使用启动缓存。
- 选课成功/已报名会登记防重；手动博雅签到成功也会登记到后台done记录。
- 重复课池概览只打印首条，符合用户后续要求；应该继续保留静默同步。
- 网络凭据大体按账号分开；切换视图不会直接停止所有账号调度。
- 桌面/Headless启动确实有Windows mutex、Unix flock及端口备用检查，不能笼统说完全没有单例。
- 课程名称和日志等主要展示文本调用escapeHtml。本轮合成HTML标签没有成为可执行标签；问题是其他上下文的插值漏防。

这些机制有价值，但每一条都有边界：三次逻辑尝试不等于三次POST；非空点不等于有效配置；静默运行不等于用户能识别故障；独立账号状态不等于每账号异常隔离。

## 7. 四种视角下的产品缺口

| 视角 | 优先关心 | 当前缺口 |
| --- | --- | --- |
| 用户 | 有没有选错课/签错人、是否真的达标、能否及时停止 | 身份绑定、停止保证、官方结果/缓存状态分离、配置未知提示、健康面板；不能只显示“已启动” |
| 产品负责人 | 承诺是否可兑现、目标是否可控、出问题能追责 | “全量”“高强度安全”“毫秒级”“100%可靠”与实现不一致；抢课目标/上限/类别预约策略不清晰，缺发布来源清单 |

1. **阻断错误写操作和钓鱼入口：** TLS/管理认证/Origin与Host、去inline事件、准确账号、合法ID与sign_type、拒绝默认坐标、取消错误ID退选兜底。
