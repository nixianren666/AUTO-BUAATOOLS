## 入口与级联影响

旧逻辑允许未激活账号打开完整TD页面，仅禁止学校写入；激活卡片支持关闭/Esc/遮罩。这是旧设计边界，未满足用户新的“先激活才进入”要求，并非签名失效。

现在点击TD先以管理会话查询当前学生的本地`/api/td/license/status`，核验期间保留之前的课堂/博雅页面。未激活或到期时只弹激活卡片，不显示TD进度、图库或任务数据，不加载全量TD状态与照片。卡片隐藏关闭按钮；Esc、遮罩及通用/增强浮层管理器均不能关闭或替换它。明确的“返回常规课堂”取消本次进入，不授予TD访问；防止把其他免费功能一起锁住。激活成功且返回有效授权后才进入TD，已激活账号每次进入也重新查询。

核验超时、网络/本地服务异常、无效响应、无效激活码均保守锁定。离开/换账号使旧请求失效，旧响应不能打开新账号TD。已在TD时，状态发现失效或到期定时器触发，会退出TD并重新核验；隐藏恢复沿用原生命周期。无账号先进入账号中心。日常常规/Boya请求、校方API字段、调度重试和TD配对/图片组/每日预算不改。新增接口只查本地签名授权，不请求学校、不用打卡冒充查询。

通用浮层及原生模块加载失败时的即时fallback均执行同一个入口限制。此层是页面访问控制；后台TD每次真实请求前的验签/到期约束仍独立保留，不以隐藏界面替代后端校验。授权算法、公钥、首次激活一个自然月、核销与时钟机制保持。

## 生成器报错

用户截图是“未找到签发私钥”，发生在签发前；没有证据表明签名算法本身失效。当前本机原私钥仍在、可由当前系统用户解密，且匹配客户端公钥；未重生、复制进包或替换它。旧版只读LOCALAPPDATA环境变量，Windows新实现直接通过Known Folder API定位当前用户实际LocalAppData，不依赖启动器继承的环境。启动时显示私钥存在/可解密/匹配的自检结果，另提供不输出私钥/激活码的诊断报告参数。

真实编译生成器在正常环境及LOCALAPPDATA故意误指目录时均通过诊断，使用原钥签发的合成账号申请可由真实客户端编译模块激活，重复核销和跨账号拒绝。截图当时进程已退出，未采集其原始环境，因此不能断言环境变量误指是该截图的唯一原因。若在另一个Windows用户/电脑运行，仍需维护者自行导入加密备份；不会把私钥内置或绕过验证。
