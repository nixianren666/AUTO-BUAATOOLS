# v1.4.18 短信登录与学校请求安全

## 来源与适用范围

用户随后确认，先前在 UBAA 看到的是图形验证码。复核表明，学校统一认证响应提供 `config.captcha` 和验证码 ID，UBAA 从学校 `/captcha` 取图，再向学校 `/login` 提交本人填写的答案。直连、WebVPN 和公开源码中的后端代理最终都指向学校 SSO。UBAA 自行实现的是提示、展示和会话管理。学校决定何时要求图形验证码，公开客户端源码无法说明具体触发阈值。此前的 UBAA 截图不再作为条件式短信挑战的线索。

核对了 UBAA 公开发行 v1.8.2、`main`、`dev`、`ubaa2`、近期 PR、问题、公开派生仓库和维护者的相关仓库。`ubaa2` 的交互认证实现能接续图形验证码，遇到 `config.mfa` 会停止。尚未找到群截图所示条件式短信验证的公开提交或协议。

继续检查了 UBAA 的 1533 条公开可达提交及 fontlos/buaa-api 的 460 条提交。UBAA 4 月 3 日提交补齐图形验证码字段，8 月 26 日已有 `config.mfa` 测试，期望是停止未知交互步骤，10 月 2 日仍有此防护。UBAA 的 Rust 分支将 buaa-api 列为冻结协议参考。buaa-api 的 SSO 公开实现取表单 `execution` 后提交密码，未发现短信收发实现。表单 `execution`、会话 token、学校短信验证码分别属于不同机制。无法根据公开历史判断学校此前是否对部分账号触发过条件式短信。

旧实现曾把学校的 `continueForm` 当作密码到期提示自动提交，而 buaa-api 的历史提交明确用该表单表示账号存在安全风险。本候选遇到风险或不明继续页时暂停，只有明确的普通密码到期提示才沿用已有可选继续流程。

北航公开统一认证页面提供独立短信登录入口。本项目按公开表单接入，由本人点击请求短信，在同一账号、接入方式和 CAS 会话中提交验证码。收到额外认证、未知验证码或风控拒绝时暂停对应账号，提示用户在官方页面处理。验证码与短期会话句柄只保留在内存。无头服务远程短信登录要求 HTTPS，本机环回可使用 HTTP。只用短信添加的账号在会话到期后需要本人再次登录。

进一步从 UBAA 的 Kotlin 登录界面、Flutter 验证控件追到各自提交路径。公开界面的验证码会加载图像、绑定会话，再提交图形验证码答案。Rust 的未知验证检测把 MFA/OTP 判为需停止的步骤。收到明确短信提示时，本候选在界面提供直接切换到学校独立短信登录的按钮，沿用已确认的直连或 WebVPN 路线，由本人再明确点击发码。如果学校仍要求原密码会话完成专门二次验证，应用继续保留暂停和官方处理入口。

## 请求控制与级联影响

| 边界 | 约束 |
| --- | --- |
| 传输 | 常规、博雅、CAS 与 WebVPN 请求在发送前共享 SQLite 滚动预算。TD 每个阶段先预留两条报文。写盘失败时停止该请求。 |
| 账号与安装 | 单账号 24/分钟、120/小时、600/24 小时。同一数据目录 60/分钟、360/小时、1800/24 小时。不同设备或不同数据目录分别计数。 |
| 认证 | 认证提交单账号最多 4 次/10 分钟、10 次/小时。短信发码单账号至少间隔 90 秒，最多 3 次/小时、5 次/24 小时，另有全安装短信上限。本人验证暂停和 429 冷却跨进程、重启保留。 |
| 调度与写入 | 常规课表例行保底同步约三十分钟，登录和签到后及时同步。网页静默、微信提醒和守护共享按学生的当日快照与读取冷却，签到结果界面优先复用后端已经拉取的快照。读取连续失败后依次等待 90 秒、3 分钟、30 分钟，随后允许下一轮检查。未发出实际签到请求的预检失败采用同样的间隔，已确认的签到提交仍按原写入预算。手动刷新和提交前必要的官方核验继续可用，待核对写入保持防重。博雅已选约十五分钟一次，课池最少三十分钟，每页按二十分钟计最短间隔。已知候选仅在官方预选窗口内按单课详情核对，间隔至少五分钟，已满可在下轮发现释出名额。提交前继续核对最新名额、已选、冲突、课程规则及窗口，未确认写入继续防重。新发布课程及短暂放出的名额可能延后发现或错过。 |
| 前端、日志、通知 | 按账号显示需本人验证，切换前台学生不改变其他账号的状态。短信发送由明确点击触发。应用限流与上游异常区分，微信发送和微信课前提醒路由保持独立。 |

以上阈值是应用自己的保护上限。学校侧风控和许可由学校决定。旧版本生产数据、本地可执行文件和发行记录保持原状。

## 验证边界

源代码隔离环境使用合成账号、真实 HTTP 客户端钩子和本地浏览器。覆盖新旧登录、直连与 WebVPN 通道、跨账号误用与单次挑战、429 冷却、并发与重启、预算耗尽和禁止重放。实际触发的条件式短信挑战、真实短信收发及四平台原生成品留待后续验收。

本轮最终源码套件 575 项、浏览器检查 136 项通过，隔离测试期间非环回联网尝试为零。四个合成账号的 5200 次持续预算申请共放行 1800 次，任一账号均未超过 600 次。另验证了博雅开窗前不查单课、释出名额可进入预检、网页和微信共用当日课表、三次读取失败后统一冷却、签到后一次读取，以及短信提示切换到原接入路线并由用户点击发码。
