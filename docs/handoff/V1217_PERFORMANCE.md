# v1.2.17：渲染性能与不可见停绘

2026-10-17，本地 Windows 候选已交付；默认EXE与v1.2.17便携版、同级Git本地源码已同步。直接基线是本轮开始前精确的本地 v1.2.16，另对照已发布 v1.2.7 `c379c018a66d882698051d01616d0700c3e46950` 的业务源码。没有提交、推送或发布 GitHub；当前公开客户端仍是 v1.2.7。机器结果见 `v1217_performance_evidence.json`。

## 本轮改变

- 点阵在鼠标移动及短暂缓动时响应，驻留稳定后保留排斥形态并停止重复绘制；流体保持独立流动。
- 定时唤醒与动画帧配合，不再跟随高刷新率屏幕空转；流体目标仍为30Hz、点阵活动时目标60Hz。隐藏期间冻结时间，恢复不快进。
- 五条宽模糊光带使用复用的半分辨率缓冲，细反射保留原分辨率；颜色、几何、顺序与玻璃材质保持。
- 侧栏 NEW 标签的呼吸效果两轮结束后静止。隔离测试确认，原先无限呼吸会使整层玻璃持续参与高刷新率合成；没有删除玻璃或关闭硬件加速。
- 增加独立呈现生命周期：Canvas、CSS、WAAPI、启动过渡统一遵守可见性。不可见时跳过正文绘制和画布重建，恢复尺寸、页面与未提交输入。
- Windows 原生网页控件同步隐藏，使用实际窗口上下层级及物理像素矩形检测完整遮挡。最小化、关闭到托盘、其他不透明窗口完全覆盖都会停绘；失焦本身、部分遮挡、其他屏幕的全屏、透明/分层窗口和自身弹窗不被直接当作完整遮挡。

前景及相关窗口位置事件优先处理，500ms计时器兜底；不能承诺所有窗口事件下瞬时检测。无法确认透明度或查询失败时保守保持可见，避免黑屏。当前完整遮挡判断针对单个不透明窗口，不计算多个小窗口拼合的联合遮挡面积。

未调用 WebView2 `TrySuspend`，没有暂停 Python 进程、认证、签到、签退、抢选、统计、重试或后台同步。浏览器自身在隐藏时可能节流前端计时器，学校任务仍由独立 Python 调度器执行。GPU占用率归零不等于释放全部显存，也不等于后台CPU为零。

## 本机原生测量

同一电脑、1280×840、相同合成账号和页面，顺序运行旧版与候选。读取该应用 WebView2 自身进程的 Windows GPU Engine 性能计数器，以下取最忙的自身引擎，**不是整卡总占用，也未把各引擎相加**。

| 场景 | v1.2.16 四次采样 | v1.2.17 四次采样 |
| --- | --- | --- |
| 可见、鼠标离开 | 15 / 14 / 15 / 15% | 2 / 2 / 2 / 2% |
| 可见、鼠标驻留 | 16 / 15 / 16 / 16% | 2 / 2 / 2 / 2% |
| 最小化 | 本轮未作旧版同场景硬件测量 | 0 / 0 / 0 / 0%，流体新增帧0 |
| 隐藏至托盘 | 本轮未作旧版同场景硬件测量 | 0 / 0 / 0 / 0%，流体新增帧0 |
| 外部全屏窗口完全覆盖 | 本轮未作旧版同场景硬件测量 | 0 / 0 / 0 / 0%，流体新增帧0 |

这是有限时长采样，不能保证其他电脑、驱动、显示器和界面场景相同，也不能据此承诺风扇行为。CPU另按自身进程CPU时间、单核100%的口径记录，不把它混作整机CPU百分比。Headless Edge 的回调/任务CPU和分项隔离另有报告，不当作原生成品硬件利用率。

可见静置还用备份的真实v1.2.16 EXE与最终v1.2.17 EXE分别复测：旧版14/15/15/15%，新版2/2/2/2%，各次前后均核实原生窗口未被遮挡。表中最小化/托盘/完整覆盖的GPU采样来自原生源码宿主；成品另通过原生零帧自测和窗口操作复验，不把不同测量阶段混成同一次成品采样。

两种尺寸、三个相同流体时间点做了画面对比：流体RGB平均差约0.14–0.19/255，99百分位差2/255、最大差5/255。全界面差异还包含版本号与时钟，不能把其最大差当作背景误差。实际查看了原生玻璃、弹窗与流光，未用低清截图掩盖明显画质变化。
