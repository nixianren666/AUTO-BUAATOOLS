# v1.4.7 TD安全修正与完整复验

2026-10-21。用户要求对TD各功能和安全机制再审查并改正不合理之处。直接基线为本地1.4.6，本轮独立修复升1.4.7。**交付状态：默认EXE、便携版及dist已更新。** 同级Git仅本地同步，未提交/推送/发布；保留配置、图库、授权、原签发器与私钥，不强制关闭用户程序。

## 一、修正的三条链路

1. **成功语义不再依任意子串。** 明确否定/矛盾回复拒绝，只有支持的完整成功格式（刷卡/打卡/签到/签退成功，可含规范的学期次数）推进；“未刷卡成功”“本次未刷卡成功”、示例、问句、非法次数及未知格式均不当作成功。照片回复中的否定或错误结构转待核验。未知/失败后保留已认领预算、停止，不盲目重试。没有真实学校返回这些否定句的证据，它们是受控合成故障输入。若学校调整成功报文，严格匹配会保守暂停；不能为了兼容未知句子恢复宽松子串。
2. **学期范围与展示一致。** 保存的学期已过期或与新官方校历不一致时，status对本学期返回count=null、out_of_scope，界面显示待核对和历史记录保留；不显示0，不删除原记录。相同有效学期内，即使活动结束也保留该学期统计。
3. **学校连接前再检查。** TD网络层在创建socket/连接前和connect完成后、sendall前均重查guard。已暂停/失效/越界时不建立连接；慢连接跨越门禁后不发报文。已有10秒绝对单次截止保留，分段慢响应不能无限延长总耗时。

## 二、六层级联范围

- 底座：仅TD结果判定和连接前门禁；学校地址、端口、报文类别、字段/设备、时间戳格式均不变。常规/Boya客户端未改。
- 调度：仅TD status对失效学期进度隐藏旧值；实际自动/手动执行策略、日预算、冻结照片组、配对截止不变。常规/Boya调度不变。
- API：原TD路由/请求结构和账号解析不改；进度三个既有字段仍为同类型，新增来源值out_of_scope，无读请求触发学校写入。
- 前端：只改TD次数说明，未知进度保留无数值的aria语义，原页面布局、材质、动画、入口授权流程保持。
- UI模板：仅必要版本与静态缓存版本，不改排布；规则、图库、手动和激活交互以本次浏览器检查核验。
- 日志：原脱敏日志/错误提示保持，不输出原始学校报文、学号、照片或激活码。待核验不庆祝，不冒充学校最终认定。

16份源码差异中9份仅版本元数据；除上述运行文件外为README候选标识和对应测试。TD许可算法、公钥、签发器源码与原生成器EXE保持，不重建签发器、不重新生成密钥。
