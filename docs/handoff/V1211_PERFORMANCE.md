## 本轮机制与审美取舍

鼠标仅排开附近点阵，流体始终独立运动。参考研究沿用[V1210_PERFORMANCE_PENDING.md](V1210_PERFORMANCE_PENDING.md)固定的公开首页源码：Stitch首页也逐点重绘，默认流体是独立视频；本轮没有编造其使用局部更新或WebGL，也没有复制第三方JS进发行包。

点阵改为保留静态网格纹理，仅恢复上次变化区域；只计算附近及尚未回位的点。空间项预计算、颜色/透明度分桶、路径合并，减少逐点`fill`提交。排斥为最大28px的渐进衰减，配合轻微扰动、淡化和青紫色变化；回位按经过时间缓动，避免因机器刷新频率不同而明显变速。快速跳动仍保留先前未回位点，不能为节省计算直接丢掉它们而留下残影。

点阵响应上限60Hz、流体上限30Hz分别控制；隐藏时暂停，减少动态默认静止，可单独开关。关闭动效并离开鼠标后停止RAF。上下文、渐变、存储、脚本或绘制失败会静态降级，不阻断业务初始化；修复了点阵失败后仍保留鼠标状态可能造成空转的边界。

流体缓存尺寸相关渐变，每帧复用同一组73个截面，减少各层重复计算。保留原流体分辨率、宽漫射、暗部、所有玻璃模糊层及原几何；细化褶皱、暗部通道与一条克制的内反射光脊，没有为性能把玻璃去掉或把背景改为静态图。两张点阵位图各自最多2560×1600，合计原始RGBA约32.8MB，加上流体与浏览器合成另计；这是以有限缓存换绘制提交，不能宣传所有场景内存/功耗都下降。

实际成品观察：流光经过卡片下方时，外卡片、内信息块和按钮能区分叠层；暗部保留文字对比。保持原圆角、文字尺寸、按钮命中范围，不增加炫光覆盖文字或额外玻璃装饰。截图只是某个光线相位，不能替代动态体验。

## 本次性能证据

同机Edge、同尺寸、相同指针/滚动路径、48张合成卡，1280×840、1920×1080、2560×1440，分别关闭/开启两层背景。每场约2.4秒，两次前后配对采用相反顺序；最终候选包含新增的细光脊。下表是2560×1440两层开启时：

| 指标 | 1.2.10 | 1.2.11最终候选 |
| --- | ---: | ---: |
| 装饰JS回调耗时p95 | 约6.9ms | 约2.5ms |
| Canvas fill调用次数 | 604,881 | 1,146 |
| 浏览器RAF间隔p95 | 约37.5ms | 约18.8ms |
| 超过25ms的RAF间隔数 | 43 | 0 |

另一配对为回调7.0→2.8ms、RAF间隔37.6→21.9ms；大尺寸改善方向一致。合并`fill`并不等于绘点/总成本按同一倍数下降，快速交互仍需画活动点。小窗口因点阵响应频率提高，总JS时间未必下降。**这些是短时无头浏览器数据，不是原生呈现帧率、GPU完成时间、所有硬件流畅保证或多小时功耗测试。** 原生窗口另由computer-use实际操作确认可用，未据此宣称锁60帧。
