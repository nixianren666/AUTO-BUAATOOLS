## 当前行为

| 条件 | 实际处理 |
| --- | --- |
| 手动窗口 | 本人北京时间当日排课，开课前10分钟至本节下课（端点包含）；上课期间可以提交 |
| 自动首次 | 优先课前10分钟内随机时刻；若启动时课程已开始且未结束，可立即进入资格检查 |
| 明确失败 | 每组最多3次实际POST，最多2组、同账号同课同日共6次；组内至少30秒 |
| 组间 | 仍在课前至少60秒；开课后至少300秒，从上次失败完成时间计；巡检/网络可能使执行更晚 |
| 跨开课 | 每次决定和持久账本原子认领时重新判定；学校时间已开课也用300秒，不重置总次数 |
| 成功或官方已签到 | 停止重发并刷新官方课表 |
| 超时/不明确结果 | 保留待确认记录，仅同步官方状态，不自动重放 |
| 下课时间缺失、错误或倒置 | 不臆造45/90分钟，仅保留课前至开课窗口；未知考勤状态不提交 |
| 连接未建立 | 不消耗实际POST预算；自动任务至少退避30秒再预检 |

手动、自动、重启后连接均使用同一个持久防重账本。快速点击、并发、切换开关和重启不重置实际提交次数。有限重试是程序策略，不是学校风控阈值，也不保证签到一定成功或免于审查。

## 六层影响及审查

1. 底座：仅常规 `iclass` 最终写入资格扩展到真实下课；学校接口地址、参数和身份校验保持。新增只读账本查询；官方时间偏差30秒上限不变。持久认领等待后再查日期、账号/暂停/窗口，防止慢操作越过下课。
2. 调度：首次随机与允许窗口分离；持久计数优先，第一组失败后课前1分钟、课后5分钟；手动失败可替代未执行的随机初始目标。异常巡检保留等待，不空转。暂时缺失/已过期的课程时间只阻止当次提交；继续同步官方课表，补齐可信时间后可以重新判定，不永久锁死课程。多账号隔离、移除/连接代际/暂停保护保持。
3. Web API：`server/app.py` 字节不变，管理会话/CSRF、账号归属、序列化与原请求链保持。
4. 前端：只有 `renderClassesList` 函数AST变化（按钮窗口及提示）；其他函数、事件绑定、原请求地址和载荷全部一致。博雅筛选修复保留。
5. 布局：仅课程/手动弹窗说明及版本文字；所有CSS、流光点阵、启动和渲染生命周期文件与1.2.20字节一致，未恢复已撤销的可见性能优化/遮挡检测。
6. 日志/通知：超限/窗口结束/待官方确认明确记录；不确定提示只记录首条。新测试仅合成数据，不提交账号、密码、Cookie、配置或截图。

同类风险复核：启动于课中、课前跨开课、慢读/慢账本跨下课、重启/手动自动共享预算、三次后与六次上限、连接失败退款、成功立即刷新、结果不确定不重发、未知结束后官方补齐时间可恢复、未知结束保守处理均覆盖。Boya及通用账本调用仍默认旧的3次上限且不启用常规冷却，新限制只对常规调用显式生效。
