## 已实现的功能链

1. 学生账号中心仍是唯一账号来源。TD 使用该账号学号，不接受另一个任意学号、卡号、密码或设备服务器地址；不发送 SSO 密码/Token/Cookie。没有第二个 TD 用户列表或登录弹窗。既有账号即使课堂授权暂时失效，TD 仍按自己的开关与校园网条件处理。
2. 新增侧栏“自动 TD 守护”，玻璃规则弹窗、学期/今日进度、活动范围、阶段提示、拖入/多选导图、缩略图、全选/删除和终端 TD 日志。复用现有玻璃下拉、浮层互斥、焦点约束及过渡，不更换原其他页面。
3. 照片存于配置文件旁的 `配置名.td-private/`，账号目录为摘要，图片标识为随机 ID。单张8MB、1600万像素、仅静态JPEG/PNG/WebP，每账号最多100张/100MB；去 EXIF、限制尺寸、重新编码JPEG并生成缩略图。仅通过已有管理会话保护的 `/api/td/images` 读取，禁缓存，拒绝跨账号ID及路径穿越。
4. 入口、出口分别选择照片，有多图时避免相邻两次使用相同照片；同轮预先冻结两个图片ID和机位。配对或待核验图片禁止删除。不复制上游固定一学期两张照片或跨账号全局图库。
5. 守护默认关闭，用户必须填写当前学期活动日期、校区/目标/每日预算并确认本人参与。旧春季公告不能自动填成当前秋季规则。固定历史公开允许时段07:30–10:00、11:30–14:00、15:30–20:00（北京时间），规则变化时应停用并调整实现，不能自动把旧时间当未来保证。
6. 每轮入口、照片、等待180–240秒、出口、照片；入口到后续实际发包严格少于420秒。每个网络发包前重查当前账号、开关、活动范围、实时窗口与配对截止。入口请求和其照片使用同一时间戳，出口亦然。
7. SQLite 在发包前写入认领，事务隔离跨线程/进程争抢。`sending_entry/exit → waiting_exit/idle`，网络未知或明确失败进入 `uncertain/rejected` 并暂停。重启遗留 sending 不能重放；有效 waiting_exit 可以恢复，过期/跨日不补发。每日本软件最多三轮，失败与未知也耗预算，人工解除暂停不返还预算、不补记成功。
8. 成功配对只表示请求及照片被接收，不等于学校最终有效次数。未知计数为 null/“待核对”；服务器计数和手动核对次数均显示来源与更新时间，按活动范围隔离。计数达到目标停止新轮，但仍完成已经开始的有效配对。不复制上游 `query_count` 的入口写请求；刷新本地状态不会打卡。
9. 移除账号先标记 removed，所有发包前检查即失效，再暂停 TD 并完成原客户端清理。保留图库不擅自删照片；需清理可在移除前操作。修改结构性规则不能绕过未完成/待核验配对。关闭或最小化界面不终止后台业务；隐藏页面停止 TD 状态轮询。

## API 与模块

- `core/td_client.py`：固定校园端点、受限帧长、全请求10秒预算、保守成功识别；原始学校 TCP 本身没有TLS，不能宣传传输已加密。
- `core/td_store.py`：私有图库、计数与SQLite日账。
- `core/td_scheduler.py`：逐账号状态机，最大四并发，空闲5秒扫描本地数据，不每5秒向学校发包。
- `server/td_routes.py`：显式 username、现有 session/CSRF/Origin/Host 边界，异步阻塞工作下放线程。
- `server/static/js/td.js`、`css/td.css`：账户世代隔离、过期请求丢弃、稳定图库、可见时15秒本地读取、重复点击保护。
- GET `/api/td/status`；POST `/api/td/settings|toggle|count|resolve`；POST/DELETE `/api/td/images`；GET `/api/td/images/{id}`。不存在学校次数读取副作用接口，不接入上游遥测/Cloudflare/D1。
- 参考 AutoTD 0.1.15 的协议/设备表，保留 [第三方许可](../../THIRD_PARTY_NOTICES.md)，不变更其许可署名。
