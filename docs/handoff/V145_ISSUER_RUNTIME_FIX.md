# v1.4.5 维护者私钥实际存储修复

2026-10-21，用户报告新签发器仍找不到私钥。本次已定位并修复本机运行环境，不修改任何生产源码或二进制，不升为1.4.6；程序仍为已交付1.4.5。审查目录名称中的v146仅为调查目录，不代表软件交付版本。

## 确认的根因

同一文件名、同一Windows用户、同一AppData字符串仍存在两个文件系统视图。测试进程的私钥文件句柄解析到Codex包的`LocalCache/Local/AUTO-BUAA-TD-Issuer/signing-key.dpapi`，并非桌面普通程序实际读取的LocalAppData目录。原始加密私钥在应用缓存中；从真正Explorer启动的GUI及独立Python均确认实际目录中的文件不存在（WinError 2）。

此前测试从Agent或Shell COM直接启动，仍继承该文件系统视图；此前报告的“Explorer启动”未等于真正Explorer启动，这是上轮验收缺口。Known Folder接口虽修正了环境变量依赖，但不能消除文件I/O重定向，不能再把其测试成功当本机双击已修复。

本轮以真正Explorer执行项目外快捷方式，并记录普通用户上下文中的GUI/文件系统前后对照。保留证据`real-explorer-gui.json`及`real-explorer-filesystem.json`的原始失败，不覆写成成功。

## 修复与隐私边界

由普通用户上下文将同一份DPAPI密文放入真实LocalAppData的维护者目录；复制前在内存验签公钥匹配，复制后字节一致，未生成、替换、明文写出或打包签发私钥。目标目录/文件DACL仅授予当前用户、SYSTEM与Administrators，未授予Everyone。应用缓存中的原密钥保留，不删除。

在事务中合并原签发库3条记录与目标库：同一申请已有不一致签发结果时会中止，不覆盖；原库保留。所有内容仅在维护者私有目录及内存处理，不输出申请码、激活码或密钥。原用户配置、图库、客户端授权和期限均不变，未触发学校请求。
