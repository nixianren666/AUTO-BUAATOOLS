## 六层连锁检查

网络原始字段在domain契约中解析；调度与手动入口复用actions；API输出官方状态和操作能力；JS绑定账号代次、只消费明确能力；HTML按钮与未知提示一致；日志分清未发送、拒绝、结果不明、接受及官方确认。修改状态/日期/ID/容量时按这条链共同调整，避免前端重算引回已修缺陷。

## 三种实际验收视角

- 用户：官方数据与缓存/未知能分辨，切换学生不混号，成功后按钮更新，守护暂停透明，目标表单和弹层可操作。
- 负责人：保留v126与撤回微信，不把单一平台/Mock结果夸成全平台、实际学校写入或未来风控保证；Release须带完整同期资产与来源。
- 工程审查：延迟跨窗口、旧响应、同名异ID、坏字段、重复分页、超时后批次、连接建立前失败、CSRF、密钥异常、停止/移除、升级卸载及长期清理都有契约验证。

尚不能宣称实测重启登录后的系统自启、连续数月挂机、所有学校未来数据形态或未OCR的历史图片零信息。本地账号信息和截图不得作为公共验收证据。

补充反例：存储失败不能造成界面关闭而后台暗中开启；暂停请求优先保持停止，并提示配置未落盘。系统自启返回真实状态而非所请求值；卸载只移除指向当前安装文件的自启项。考勤/考核字段中的小数、空字符串及未知枚举不能被int转换成可操作状态。
