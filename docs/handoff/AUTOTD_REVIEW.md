# AutoTD：风险、未实现的保护及前端重构依据

2026-10-19。范围、版本与完整链路见[AUTOTD_MECHANISMS.md](AUTOTD_MECHANISMS.md)。本报告只分析，没有修改上游或本项目的生产逻辑。

P1 表示优先处理的隐私、误操作、权限或结果可信度问题，不表示已在真实部署中利用；P2 为可靠性与维护风险，P3 为交互/展示完善。探测编号 P/F/C 对应本轮后端、前端 VM、历史云端 SQLite/VM 证据。

## 一、先区分四种“成功”

1. socket 正确收到 JSON：只说明传输/解包成功。
2. 返回文字被 `check()` 判为 success：依赖宽松的子串规则。
3. 本机状态达到 completed 或遥测产生 delta：属于本机执行及统计模型。
4. 学校认定有效锻炼并计入正确学期：还涉及规定、配对、本人记录与最终审核；本轮未触碰学校服务端。

这四层不能互相代替。尤其“没有抛异常”“接口返回 200”“缓存达到 32”“网页绿色提示”都不是最终学业结果保证。

## 四、遥测的稳定性与隐私生命周期

- **队列竞态**：flush 先读取旧事件列表，再整文件覆盖/删除；发送期间新事件可被抹掉（P21）。
- **关闭竞态**：disabled 并未通过锁/版本与调度状态隔离，旧 poll 保存可将其恢复（P20）。这是隐私优先项。
- **阻塞**：同步逐事件网络发送和每次错误写 state 没有总预算，积压大时明显拖慢 CLI/UI/守护；没有指数退避、批次上限或容量上限。
- **容错缺口**：坏队列 JSON 在 try 之前解析（P25）。HTTP200 内部错误体也被当作成功而丢队列（P22，属于防御性缺口，不能据此断言当前 Worker 正常路径正在返回错误的 200）。
- **endpoint 变化**：保留 registered=True；没有强制 HTTPS（P23–P24）。默认 endpoint 是 HTTPS，不应据此反过来称默认传输无 TLS。
- **数据删除**：关闭只清本地队列，删除本地用户只上报删除快照；不删除云端历史（C14）。不能把“已关闭/已删除”宣传为远端忘记。
- **统计可信度**：客户端只把出口正增量计入 delta，是有意减少假增量；但云端仍信任客户端自行申报的数据（C02），跨安装同用户也可能重复统计观察到的增长，不能当学校最终成绩。

## 六、如果未来讨论重构，应该如何划分

这不是本轮修改授权，以下只是工程边界建议：

1. **先确定允许的功能范围**：本人实际参与、官方只读查询/提醒和本地记录与模拟设备写入不是同一风险；不能把随机等待当合规或免识别保证。
2. **统一任务执行器**：手动/后台共享一套按用户、学期、日期、阶段建模的状态机；请求前持久认领，未知结果先核实；取消、暂停和停止各自定义。
3. **分离可靠查询与写入**：没有独立只读接口时，刷新数字必须明确潜在副作用，不能隐藏在普通刷新操作里。
4. **先补隐私和管理权限**：默认关闭第三方遥测、明确同意及删除边界；本地接口限回环、鉴权、CSRF/Host/Origin 检查、上传限制。
5. **以正式规则建模**：学期、开放日/窗口、入口时刻、阶段截止、每日实际配额、本人/图片依赖；官方确认与本地完成分开。
6. **前端围绕任务结果重做**：待执行/请求中/等待/待核实/成功/失败/已停止，显示更新时间与缓存来源，处理旧响应和多入口并发；功能正确后再保留本软件既有美术。
7. **云端若无必要就不要引入**：若确需统计，匿名聚合与默认不采集标识优先；注册权属、事件归属、事务、重放及 HTML 转义需要完整闭环。

## 七、本轮没有声称什么

未将这些问题说成我们的 v1.3.9 已有问题；未恢复旧功能或修改签到策略。没有认定作者恶意、没有实际获取维护者管理权限，也没有保证所有边界都能在生产环境利用。原有 68 项测试通过与新增 61 项边界/正向探测，不能取代真实学校授权验收、长期后台、多平台原生 UI 和生产部署检查。

源文件及逐函数定位见[AUTOTD_CODE_INDEX.md](AUTOTD_CODE_INDEX.md)。后续讨论应引用具体版本和探测编号，而不是泛称“AutoTD 安全/不安全”。
