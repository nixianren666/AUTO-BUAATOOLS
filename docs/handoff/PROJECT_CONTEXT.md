# 产品与工程背景

证据范围：UBAA123 本地历史会话与 2026-10-12 工作区源码。以下分别描述业务要求和当前实现，不代表已重新验证学校接口。

2026-10-13 更新：用户要求抛开 Antigravity 认知，重新分析 UBAA / AutoBoya。技术原理改以 [独立上游机制报告](UPSTREAM_MECHANISMS.md) 的固定源码、调用链和离线探测为依据；此文件继续记录产品背景和用户要求。UBAA 在所核查签到/博雅路径中是用户点击触发；AutoBoya 的自动循环是每小时网络刷新、每分钟缓存扫描，不能混为本项目新增的课前自动签到/60秒课池网络同步。

## 产品定位

用户最初要把 `BUAASubnet/UBAA` 的课堂签到单独做成轻量桌面软件，有现代 UI、Windows EXE 和安装程序。之后引入 `DeNeRATe-cool/AutoBoya` 的博雅功能，并扩展到多账号和多平台。

- 主品牌：AUTO-BUAA；仓库名：AUTO-BUAATOOLS；可执行程序：BUAA-Signin。
- 公开仓库地址：`https://github.com/nixianren666/AUTO-BUAATOOLS`。2026-10-14已恢复main到v1.2.6提交5158df8，删除v1.3 Release/标签并恢复默认EXE，见VERSION_WITHDRAWAL.md；10-13的GITHUB_AUDIT.md保留旧状态证据。
- 上游参考是机制与协议研究来源，不代表当前接口可以永远照搬，也不代表已获学校方面的稳定性保证。
- 根 AGENTS.md 的“晨午检”措辞与实际核心功能有出入：本次所见代码主要是 iClass 常规课堂签到与博雅系统，未确认独立晨午检业务模块。后续不能仅据该措辞新增或宣称已有功能。

## 功能契约

### 多账号与常规课程

- 账号卡支持添加、切换、移除学生，以及独立启停守护。切换只改变前端当前视图，其他学生的后台任务不能停止。
- 每个账号有自己的网络会话、今日课表、博雅缓存和日志；不能把全局当前账号误当成唯一后台服务对象。
- 常规自动签到严格在 `[开课前10分钟, 开课时刻]` 内随机安排，最多三次总尝试。禁止为了“补签成功”擅自延伸窗口。
- 上游提交需要排课实例 ID：优先 `courseSchedId`，不能混淆为课程目录的 `courseId`。保留时间、教师、教室、签到状态等原始字段。
- 签到成功后应重新查询官方课表。用户曾遇到早上已签到、中午仍显示未签到，手动刷新才恢复的缓存问题。
- 网络模式为 auto/direct/webvpn；校外直连失败要有有限超时和降级；认证过期需要重连，不能把请求失败伪装成“今天没有课”。

### 博雅课程

- 选课池、已选课程、四类筛选（德育、劳育、美育、安全健康）、可选/线上自主打卡筛选、搜索、手动选退课、自动抢选和自动签到/签退。
- **自动抢课只允许可线上自主签到/签退的课程。** 用户在误选线下课后进一步要求去掉可关闭这个限制的开关。UI 的课程筛选按钮与自动化安全开关不是同一件事。
- 当前 `has_autonomous_sign` 按签到配置中的非空 `signPointList` 判断；是否足以保证有效坐标和完整时间窗口仍需校验，不能把函数名当作保证。
- 自动签到覆盖所有官方已选课程，包括用户自己在官网选中的课；不能只覆盖本软件抢到的课。缺失配置时尝试从全量课池补齐。
- 使用官方签到/签退窗口和定位配置；签到、签退分别防重、分别有限重试。当前代码另有时间窗口兜底，需结合官方协议复核，不能将兜底描述成官方规则。
- 自动候选还要检查校区、容量、课程开放/取消/结束状态、选课时间和时间冲突；抢中或服务端提示已报名后不再重复提交。
- 课程真实 ID 与报名记录 ID 分离：`courseId`/归一化 `id` 表示课程；`chosenCourseId` 保存报名记录。退选接口 `delChosenCourse` 的参数名是 `id`，不能凭名称猜成 `chosenCourseId`。
- 已选页区分“未来及正在进行”与“历史选课”。结束后不应保留退选/签到/签退操作；按钮要反映官方“已签到/已签退”，不能仅靠点击动作本地置成功。

### 学期达标

- 用户给出的项目标准：德育 2、劳育 2、美育 1、安全健康 1，总计 6 门；这是每学期要求，不是毕业累计要求。
- 达标要求考勤与考核都通过；“选中”“签过一次”“拿到学分字段”不自动等于最终达标。
- 优先使用官方 `semesterInfo.semesterStartDate` 和 `semesterEndDate`。历史累计单列，禁止污染当学期进度。
- “安全健康”是用户纠正后的名称；“国家安全”是历史误称。
- 官方累计统计、当前学期达标、自动选课需求缺口是不同概念。当前代码对自动候选缺口按本学期已选数计算，不能宣称等同已通过数。

### 日志、后台与桌面

- 按账号分隔，账号下有总日志、常规日志、博雅日志；常规日志不应混入博雅操作。
- v1.2.6：成功操作后刷新；重复课池概览仅首条，后续同步静默。正常事件与异常仍需可追踪。
- 关闭窗口隐藏至托盘，继续守护；重新启动或托盘操作应恢复既有窗口，避免多进程、多托盘。退出应用才停止服务。
- 开机自启必须可开关；首次使用有免责声明确认。Mac 托盘需显式恢复入口，不能照搬 Windows 点击习惯造成隐藏后无法唤回。
- Windows 安装/便携、Mac DMG/ZIP、Linux/Headless、Docker 都属于交付范围。源码通过测试不等于每个打包客户端已验证。

## 当前实现地图

| 层 | 文件与责任 |
| --- | --- |
| 启动/桌面 | `run.py`：SafeStream、单实例、托盘、pywebview、Headless、默认端口 18346 |
| SSO | `core/cas.py`：CAS 表单、验证码/错误解析；`core/webvpn.py`：WebVPN URL/主机加解密 |
| 常规网络 | `core/iclass.py`：httpx 异步客户端、SSO/iClass 认证、课表、签到 |
| 常规调度 | `core/scheduler.py`：一个 asyncio 后台任务遍历启用账号；独立状态不等于每账号独立线程 |
| 博雅网络 | `core/boya_client.py`：同步客户端、认证、加密 API、课程归一化、选退课、签到签退 |
| 博雅加密 | `core/boya_crypto.py`：请求/响应加密与本地秘密编码函数；具体密钥保护强度不能据 README 断言 |
| 博雅调度 | `core/boya_scheduler.py`：一个 daemon 线程遍历账号，缓存同步、筛选、防重、熔断、签到签退 |
| 自启动 | `core/autostart.py`：Windows 注册表、macOS LaunchAgent、Linux systemd 用户服务 |
| API/状态 | `server/app.py`：AccountState、账号集合、配置持久化、API、日志、课程状态与学期统计 |
| 正式前端 | `server/static/index.html`、`css/style.css`、`js/app.js`：原生 HTML/CSS/JS，无 Vue 构建依赖 |
| 构建 | Windows/macOS `.spec`、`installer/setup.iss`、`.github/workflows/build-macos.yml` |
| 服务部署 | `scripts/install_linux_service.sh`、`install_macos_service.sh`、`systemd/`、Docker 文件 |
| 新 UI 实验 | 根目录 `preview_liquid_ui.html`、设计提示词、贴图与各类 `test_*.html`；独立于正式页面 |

主要 API 族：`/api/status`、`/api/accounts*`、`/api/login`、`/api/classes`、`/api/signin`、`/api/auto_checkin`、`/api/boya/{status,courses,selected,statistics,refresh,select,drop,sign,toggle_auto}`、`/api/logs`、`/api/system/{disclaimer,autostart}`、`/api/health`、`/api/window/show`、`/api/exit`。精确参数以函数和 Pydantic 模型为准。

当前周期：常规默认 20 秒；博雅默认 60 秒；白天全课池约 60 秒、已选约 300 秒；23:30–07:00 同步间隔改为 1800 秒，外层循环等待 180 秒。前端日志约 2.5 秒，活动视图约 25 秒。宣传中的“毫秒级巡检”并非整个调度循环的真实频率。

## 设计偏好与工作方式

- 用户用中文交流，希望过程说明和交付文字清晰、持续；反复担心任务卡住、断线、限额或重启后工作没有真正接续。
- 强调细节和完整性，不接受“测试通过”一句话代替实际使用验证；尤其重视安装包、绿色版、源码和不同平台是否同版。
- 曾接受 Origin 风格的功能排布与 Emil Kowalski 风格微动效；后续允许从零重构 UI，但不能遗漏业务功能。
- 喜欢克制的结构、清晰层次、留白、不同窗口尺寸适配；不喜欢把所有监控数据堆成路由器后台。
- 液态玻璃目标是浅色、通透、折射高光与动态弹性；不是深灰遮罩或普通大范围 blur。曾要求 Stitch 风格鼠标排斥粒子，后来使用湖景背景检验玻璃透光。
- 最新预览有四个光学调参滑块；这是实验工具，不自动推翻正式产品“透光控制保持简单”的偏好。
- 历史要求先验证便携版再封安装包。用户之后的明确发布指令可覆盖此顺序；不能把过期发布指令当成本轮授权。

## 隐私与权限边界

原始日志曾出现真实测试账号、GitHub 访问凭据、SSH 连接信息和个人截图。交接只保存脱敏摘要与定位信息。历史敏感内容不应复制到新测试、文档、工具输出或仓库中。

本地账户数据路径由 `resolve_config_path` 决定，涉及源码目录、便携 EXE 邻目录、Windows AppData、macOS Application Support、Linux 用户配置目录，并可能迁移旧配置。启动程序可能自动恢复保存账号；验证时必须隔离配置和网络写入。

本地 WebUI 是管理面；当前没有看到独立管理端认证层，Headless 默认对外监听且 CORS 宽泛。不要将“SSO 登录学校”误当成“Web 管理端已做访问控制”。这是源码审阅发现的部署风险，不是本轮执行过的渗透测试。
